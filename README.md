# 日常留白 · 極簡個人記帳 v1

繁體中文、手機適配、無需安裝套件的個人記帳網頁。原始碼可公開，輸入的帳目只保存在使用者自己的瀏覽器，程式不會將帳目傳送到 GitHub。

## 開始使用

1. 開啟已部署網站，確認顯示正確週期；例如「2026 年 11 月」表示 2026/11/05～2026/12/04。可切換任意月份，包括 2027 年 2 月及以後。
2. 本期設定可修改實領收入及儲蓄目標。預設值可於介面調整。所有實際金額、餐費預算與目前存款均為空白。
3. 點每日早餐／午餐／晚餐，填入預算、實際金額並勾選完成；未知留空，確認沒有花費填 0。勾選完成必須有實際金額。
4. 點「其他」新增多筆明細，選擇房租、水電網路、車資、信用卡費、分期款項、醫療、娛樂、人情、飲料、宵夜、其他。
5. 已有固定支出請點「其他」中的房租／訂閱／加油入口（或下方固定支出卡片）記錄付款，系統更新原本那一筆，不再額外加總。實際金額是本期累計付款，付款日期是最後指定的日期。也可修改預算；無該項支出時將預算與實際設成 0。
6. 「更新存款」填入實際目前存款，顯示 2028 年 20 萬目標進度。建議於期初更新基準。每期結餘不會自動轉為存款。
7. 定期匯出備份，換裝置時手動匯入。匯入會取代所有週期；先檢查確認提示。原資料會自動下載一份備份（需允許瀏覽器下載）。

固定支出對應由使用者明確選擇：若自行新增一筆「房租」明細，仍會被視為額外支出。信用卡帳單若已包含記過的消費，請勿再次記整張帳單；僅記未入帳的差額。v1 不自動辨識信用卡交易或拆分多次付款日期。

## 計算規則

- 本期預算＝所有餐費預算＋「其他」明細預算＋固定支出預算。
- 已花費＝所有實際金額加總，不受完成勾選影響。
- 可用餘額＝本期收入－已花費，**尚未扣除待付支出及儲蓄預留**。
- 預估總支出：未完成項目取 max(預算, 實際)；已完成項目取實際金額。
- 本期預計可存＝本期收入－預估總支出。
- 儲蓄目標差額＝本期預計可存－月儲蓄目標。
- 預計期末存款＝手動填寫的目前存款＋所選本期預計可存。這是估計，非銀行餘額；若目前存款已含本期存入款項，應調整基準，避免重複相加。
- 目標進度＝手動填寫的目前存款 ÷ 200,000。未知時不宣稱有實際進度，超過目標可顯示超過 100%。

空白代表未知，計算暫以 0 加總。餐費或既有明細預算未填會提醒「預算尚未填齊，估計可能偏高」；尚未建立的額外費用無法預測。所有金額為新台幣，最多兩位小數。

每個週期設定獨立，新週期以已知預設值開始，不繼承上一期付款／花費。月曆依裝置本地日期決定「本期」。

## 資料保存與限制

GitHub Pages 是**靜態託管，沒有後端、帳號登入或跨裝置同步**。資料在 localStorage（`minimalist-ledger-v1`），依瀏覽器、使用者設定檔與網站來源分開保存。更換自訂網域、從本機網址換到正式站、清除網站資料、更換裝置、無痕模式，都可能讓資料不可見或遺失。

每次成功儲存前會保留上一版本於 `minimalist-ledger-v1-previous`。它只是同一瀏覽器內的補救資料，不是外部備份。讀取損壞或儲存失敗會明確提示，不顯示成功；損壞資料不自動覆寫，可先匯出原始內容，再匯入有效備份。多分頁衝突會拒絕覆寫並要求重新整理；v1 沒有協作編輯，請避免兩個分頁同時記帳。

JSON 匯入會驗證版本、日期、分類、金額、完成狀態，限制 10 MB。不合法備份會拒絕，保留原資料。備份未加密，含個人財務資訊；**不要將備份提交至公開 GitHub 倉庫**。公開網站的預設數字與原始碼可被任何人查看；實際帳目不寫入原始碼。

## 本機執行與測試

需要 Node.js 20 以上，無套件依賴：

```sh
npm start
# 開啟 http://127.0.0.1:4173
npm test
```

也可直接開啟 `index.html`，但 file:// 的儲存行為依瀏覽器不同，建議使用固定 HTTP 網址或正式 Pages。部署只需 `index.html`、`style.css`、`core.js`、`app.js`，所有引用均為相對路徑。

## GitHub Pages 部署（獨立倉庫）

1. 將此專案放在 GitHub 倉庫根目錄（不要只上傳 zip）。
2. 開啟倉庫 Settings → Pages。
3. Build and deployment → Source 選 **Deploy from a branch**。
4. Branch 選 **main**，資料夾選 **/(root)**，按 Save。
5. 等待 Pages build and deployment 完成，從 Pages 設定中的 Visit site 開啟。不要僅以預期網址判定部署成功。
6. 往後更新根目錄檔案會重新部署；不需 Node 建置，也不需金鑰或設定 Secrets。

若原倉庫已有部落格等建置流程，請使用獨立倉庫；不要覆蓋既有首頁或改變原站發布來源。

部署方式依據 [GitHub 官方 Pages 設定文件](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

## 檔案

- `index.html`：頁面結構與使用說明。
- `style.css`：桌面月曆與手機每日卡片。
- `core.js`：日期週期、計算與備份驗證；可供 Node 測試。
- `app.js`：互動表單、localStorage、匯入匯出與衝突處理。
- `server.cjs`：僅供本機預覽，只對本機介面提供網頁資源。
- `tests/`：日期邊界、金額計算、備份與儲存失敗測試。

v1 不含銀行串接、收據辨識、雲端同步、離線快取或自動存款入帳。
