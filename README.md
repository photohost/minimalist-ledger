# 日常留白 · 極簡個人記帳 v1.8.0

手機優先的每日翻頁卡片，搭配五個書籤：記帳、總覽、分析、設定、關於。使用格子稿紙背景與 Adobe 思源宋體繁體中文台灣字型；網頁原始碼公開，實際帳目可儲存到私人 GitHub 倉庫。

## 每日與月曆

卡片下方預算細項靠左、文字樣式一致；每日頁面不設日期選擇器，可用前後翻頁或總覽月曆前往指定日期。

- 每日卡片提供早餐、午餐、晚餐、其他；只填實際金額，按儲存即記帳；無每日預算或完成勾選。空白表示未知，確認沒有花費填 0。
- 00:00 依裝置本地時間自動翻到今天，從背景恢復時也會檢查。表單跨午夜仍存回原本日期。
- 每個記帳週期為當月 5 日至次月 4 日。
- 總覽採自然月七欄月曆，點日期開啟當日開銷清單，並可前往該日編輯。1～4 日屬前一記帳週期，以淡色虛線標示；月曆日期與期別統計的範圍不同。
- 當日金額與月曆只包含三餐及其他；固定支出獨立統計。非今天灰色稿紙，當日三餐或總花費超出均分額度時優先紅色，標示超支並保留原字型。

## 固定支出：房租與訂閱

設定的固定支出只保留房租、訂閱兩個入口。點訂閱可新增多筆訂閱名稱、每期金額、實際付款與付款日期。每期金額只是預算，實際付款留空時不會被當作已花費；勾選已付清須填入實際金額。

每日「其他」不提供固定支出入口，房租與訂閱只在設定管理。每筆實際金額為當期累計付款，不是自動逐次累加。訂閱已填付款日後，再改日期會移動同一筆紀錄。

## 預算全部自行設定

新週期的收入與所有金額均留空，不預填個人財務數字。在設定中選擇週期，再填：

| 分類 | 用途 |
| --- | --- |
| 三餐開銷 | 早餐、午餐、晚餐的整期支出上限 |
| 其他 | 其他分類明細的整期支出上限 |
| 固定支出 | 房租與全部訂閱的整期支出上限 |
| 儲蓄 | 本期希望預留的儲蓄額，與消費分開 |

預算配置只套用到所選週期，不自動繼承至下期。空白表示未知，0 表示明確不配置。配置超過收入可儲存，但會提醒超出金額。

### 計算方式

- 支出預算＝三餐＋其他＋固定支出三類預算；不加明細預算，也不含儲蓄。
- 配置合計＝支出預算＋儲蓄預算。
- 已花費＝三類實際金額加總；訂閱父項不會與其明細重複計算。
- 卡片使用率＝當日三餐實際 ÷（本期三餐預算 ÷ 本期天數）。零預算有花費顯示超支，未知預算不顯示假比例。
- 本期剩餘三餐預算＝本期三餐預算－本期三餐實際。
- 固定預留＝固定分類預算與「各筆固定明細取預算／實際較大值後的總和」的較大者，付款後不重複扣款。
- 可支用總額＝min（三餐＋其他預算，收入－儲蓄－固定預留）；其中一側未知暫用已知側，均未知留空；未知固定費用未預留，應先補齊。
- 本期剩餘總預算＝可支用總額－本期三餐與其他實際（包含無日期舊支出）。
- 每日總額度＝可支用總額 ÷ 本期天數；三餐或總花費超出當日額度就轉紅。此規則不將前日未用額度累加至次日。
- 明細預估：完成取實際金額，未完成取預算與實際較大者。
- 每類預估支出＝分類預算與該類明細預估總額較大者，不重複相加。
- 本期預計可存＝收入－三類預估支出；收入未知時留空。預算未完整會提醒可能高估。
- 預計期末存款＝手動填寫的目前存款＋本期預計可存。請以期初存款為基準，避免重複計入本期已存入金額。
- 2028 年目標進度依手動更新的目前存款計算，不會把預估結餘當作實際存款。

## 消費即時分析

分析書籤包含支出分布圓環圖、三類預算使用條圖、累計花費趨勢與其他分類明細表。每次儲存後立即重算，僅使用實際輸入金額，不填示範花費。儲蓄顯示預算與預計可存，明確標示估計，非已實際存入。

趨勢圖只計入指定日期的三餐與其他，固定支出與無日期舊支出不畫入；圓環圖與期別已花費仍分列固定實際付款，因此曲線終點可能與本期總額不同。

## 舊資料相容

沿用版本 1 的備份格式，新增可選預算與訂閱欄位。讀入時轉換記憶體資料，首次儲存才寫回本機；寫入前保留上一版本。

- 舊訂閱總額保留為「既有訂閱（未分類）」明細，可自行改名。
- 舊加油等非房租／訂閱固定項目移到其他，不遺失預算或實際金額。
- 已知付款日保留；原本沒有日期的紀錄保留為未指定日期，顯示在設定的舊支出區，不自行補日期。
- 尚未設定四類預算的舊週期暫沿用原明細預算；開啟預算設定可檢視並自行調整為四類預算。

請不要在新舊程式分頁同時修改同一帳目。部署新版後關閉舊頁，重新開啟並視需要重新連線 GitHub。

## 同步狀態提示

修改帳目後，日期旁顯示「尚未同步」或「雲端同步中」，與設定／同步視窗的狀態一致。提示逐字沿 Y 軸轉兩圈並跳起落地小彈，每字延遲 0.14 秒、每輪 2.4 秒；同步完成後停止。配色沿用稿紙主題，裝置要求減少動態效果時使用靜態文字。

## Google 登入與 Google Drive

新版使用 Google 官方授權，將帳目版本直接存進個人 Drive 的「日常留白記帳」資料夾，主網站不使用 Firebase。只申請 drive.file 與基本帳號權限，Token 僅留記憶體。每次同步新增帳目版本，不覆寫舊檔；雙裝置同時更新時可選版並保留所有來源。

需先啟用 Drive API 並設定網頁 OAuth Client ID，並完成真人授權才能驗證。完整設定、舊 Firebase 帳目匯出與限制：[GOOGLE_DRIVE_SETUP.md](GOOGLE_DRIVE_SETUP.md)。OAuth 用戶端 ID 由網站管理者統一填入 google-config.js；訪客只需按 Google 登入，不建立專案、不填 ID。未設定時會顯示登入尚未開放，不假裝已可使用。

舊 Firebase 功能移至 firebase-legacy.html，僅供明確登入取回帳目；主頁不載入其 SDK。原 Firebase 指南保留為歷史資料，請勿拿 Firebase 設定貼到新的 Drive 連線欄位。

## 啟用 GitHub 儲存

- 公開程式：photohost/minimalist-ledger。
- 私人資料：photohost/minimalist-ledger-data，預設分支的 ledger.json。

1. 在 https://github.com/settings/personal-access-tokens/new 建立 Fine-grained token。此步由本人操作，不要把權杖貼到聊天或提交至倉庫。
2. Resource owner 選你的帳號，設定有效期限。Repository access 選 Only select repositories，只勾選私人資料倉庫。
3. Repository permissions 的 Contents 選 Read and write；Metadata 保持必要的唯讀權限。不要授權網站程式或其他倉庫。
4. 正式 HTTPS 網站的設定書籤 → GitHub 儲存，確認帳號與資料倉庫名稱，貼入權杖後連線。
5. 第一次選上傳此裝置帳目；換裝置先下載 GitHub 帳目。版本不同會要求選擇，取代前下載舊版本備份。
6. 後續儲存先留本機副本，約 1.2 秒後上傳。只有顯示「已同步至 GitHub」才代表完成。

權杖只在本頁記憶體，不寫入帳目、備份或瀏覽器儲存。重新整理或關閉後需重新輸入；Codex 的 GitHub 連線不會成為網頁的登入權限。僅支援 HTTPS 或本機 localhost HTTP。

GitHub Pages 只提供網頁，並非資料後端；同步由網頁呼叫 GitHub Contents API 完成。上傳會核對檔案 SHA 並確認倉庫為私人；衝突時停止自動上傳，不會自動合併。離線、權限錯誤或結果不明時保留本機副本。

帳目檔案上限 900 KB；Git 歷史保留舊版本。私人倉庫不代表端對端加密，具存取權者與 GitHub 可讀取內容，請勿改為公開。

參考：[GitHub 權杖文件](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)、[Contents API](https://docs.github.com/en/rest/repos/contents?apiVersion=2022-11-28)。

## 備份與本機

定期匯出 JSON。未同步資料僅在 localStorage 的 minimalist-ledger-v1；minimalist-ledger-v1-previous 是前一版本。更換裝置、網址、清除網站資料或無痕模式可能遺失本機內容。JSON 備份未加密，不要提交到公開倉庫。匯入上限 10 MB，會檢查金額、分類、日期及完成狀態。

需 Node.js 20 以上，執行網站無套件依賴：

```sh
npm start
# http://127.0.0.1:4173
npm test
```

部署檔案：index.html、style.css、paper.css、core.js、daily.js、insights.js、github-store.js、app.js。GitHub Settings → Pages → Deploy from a branch → main / (root)。以 Pages 成功部署結果確認，勿只根據預期網址宣稱完成。
