# 日常留白 · 極簡個人記帳 v1.10.0

手機優先的每日翻頁卡片，搭配五個書籤：記帳、總覽、分析、設定、關於。使用格子稿紙背景與 Adobe 思源宋體繁體中文台灣字型；網頁原始碼公開；帳目只存在你的瀏覽器與你自己的 Google Drive，GitHub 只放程式碼。

## 每日與月曆

卡片下方預算細項靠左、文字樣式一致；每日頁面不設日期選擇器，可用前後翻頁或總覽月曆前往指定日期。

- 每日卡片提供早餐、午餐、晚餐、其他；只填實際金額，按儲存即記帳；無每日預算或完成勾選。空白表示未知，確認沒有花費填 0。
- 00:00 依裝置本地時間自動翻到今天，從背景恢復時也會檢查。表單跨午夜仍存回原本日期。
- 每個記帳週期為當月 5 日至次月 4 日。
- 總覽月曆依記帳週期排列（5 日至次月 4 日），七欄對齊星期，點日期開啟當日開銷清單，並可前往該日編輯。月曆範圍與期別統計一致；落在次月的日期以淡色底標示。
- 當日金額與月曆只包含三餐及其他；固定支出獨立統計。非今天灰色稿紙，當日三餐或總花費超出均分額度時優先紅色，標示超支並保留原字型。

## 固定支出：房租與訂閱

金額以整元輸入。點選金額欄可使用加、減、乘、除，按「＝」查看結果或直接儲存。算式先乘除後加減，例如 `172＋35×2` 會記為 242 元。結果有餘數時會提示調整。舊帳目含角分時會顯示原金額，可保留、清除或重新輸入整元。

設定的固定支出只保留房租、訂閱兩個入口。點訂閱可新增多筆訂閱名稱、每期金額、實際付款與付款日期。每期金額只是預算，實際付款留空時不會被當作已花費；勾選已付清須填入實際金額。

每日「其他」不提供固定支出入口，房租與訂閱只在設定管理。每筆實際金額為當期累計付款，不是自動逐次累加。訂閱已填付款日後，再改日期會移動同一筆紀錄。

## 預算全部自行設定

新週期的收入與所有金額均留空，不預填個人財務數字。在設定中選擇週期，再填：

| 分類 | 用途 |
| --- | --- |
| 三餐開銷 | 早餐、午餐、晚餐的整期支出上限 |
| 其他 | 其他分類明細的整期支出上限 |
| 固定支出 | 房租與全部訂閱的整期支出上限 |
| 儲蓄 | 本期希望預留的儲蓄額，與消費分開 |

預算配置只套用到所選週期，不自動繼承至下期。空白表示未知，0 表示明確不配置。配置超過收入可儲存，但會提醒超出金額。

### 計算方式

- 支出預算＝三餐＋其他＋固定支出三類預算；不加明細預算，也不含儲蓄。
- 配置合計＝支出預算＋儲蓄預算。
- 已花費＝三類實際金額加總；訂閱父項不會與其明細重複計算。
- 卡片使用率＝當日三餐實際 ÷（本期三餐預算 ÷ 本期天數）。零預算有花費顯示超支，未知預算不顯示假比例。
- 本期剩餘三餐預算＝本期三餐預算－本期三餐實際。
- 固定預留＝固定分類預算與「各筆固定明細取預算／實際較大值後的總和」的較大者，付款後不重複扣款。
- 可支用總額＝min（三餐＋其他預算，收入－儲蓄－固定預留）；其中一側未知暫用已知側，均未知留空；未知固定費用未預留，應先補齊。
- 本期剩餘總預算＝可支用總額－本期三餐與其他實際（包含無日期舊支出）。
- 每日總額度＝可支用總額 ÷ 本期天數；三餐或總花費超出當日額度就轉紅。此規則不將前日未用額度累加至次日。
- 明細預估：完成取實際金額，未完成取預算與實際較大者。
- 每類預估支出＝分類預算與該類明細預估總額較大者，不重複相加。
- 本期預計可存＝收入－三類預估支出；收入未知時留空。預算未完整會提醒可能高估。
- 預計期末存款＝手動填寫的目前存款＋本期預計可存。請以期初存款為基準，避免重複計入本期已存入金額。
- 2028 年目標進度依手動更新的目前存款計算，不會把預估結餘當作實際存款。

## 消費即時分析

分析書籤包含支出分布圓環圖、三類預算使用條圖、累計花費趨勢與其他分類明細表。每次儲存後立即重算，僅使用實際輸入金額，不填示範花費。儲蓄顯示預算與預計可存，明確標示估計，非已實際存入。

趨勢圖只計入指定日期的三餐與其他，固定支出與無日期舊支出不畫入；圓環圖與期別已花費仍分列固定實際付款，因此曲線終點可能與本期總額不同。

## 舊資料相容

沿用版本 1 的備份格式，新增可選預算與訂閱欄位。讀入時轉換記憶體資料，首次儲存才寫回本機；寫入前保留上一版本。

- 舊訂閱總額保留為「既有訂閱（未分類）」明細，可自行改名。
- 舊加油等非房租／訂閱固定項目移到其他，不遺失預算或實際金額。
- 已知付款日保留；原本沒有日期的紀錄保留為未指定日期，顯示在設定的舊支出區，不自行補日期。
- 尚未設定四類預算的舊週期暫沿用原明細預算；開啟預算設定可檢視並自行調整為四類預算。

請不要在新舊程式分頁同時修改同一帳目。部署新版後關閉舊頁，重新開啟後重新登入 Google。

## 同步狀態提示

修改帳目後，日期旁顯示「尚未同步」或「雲端同步中」，與設定／同步視窗的狀態一致。提示逐字沿 Y 軸轉兩圈並跳起落地小彈，每字延遲 0.14 秒、每輪 2.4 秒；同步完成後停止。配色沿用稿紙主題，裝置要求減少動態效果時使用靜態文字。

## Google 登入與 Google Drive

首頁日期旁會顯示「登入中」、「未登入」、「雲端同步中」、「雲端尚未同步」或「雲端均最新」。系統會等登入檢查完成才顯示提醒。點「稍後登入」可先用本機帳本，同一分頁重新整理後仍會記得這個選擇。

同一瀏覽器的長效登入從授權日起最長 30 天。Google 專案處於外部測試階段時通常為 7 天。一般登入使用分頁內的短期授權，約 1 小時或重新整理後需再次登入。

Drive 授權過期後，可在 Google 帳號頁按「重新連線 Google」，繼續目前帳本。長效登入需要啟用同站登入服務，管理者可依 [登入服務部署指南](auth-worker/README.md) 設定。

開啟網頁會直接顯示這個瀏覽器上次使用的帳本，登入檢查在背景進行，期間即可記帳；登出後下次開啟回到未登入的本機帳本。檢查點會記下雲端檔案版本，回到網頁時若 Drive 版本未變就不重新下載整本帳。登入後每次儲存先寫入此瀏覽器，重新開啟並登入同一帳號後可取回待同步帳目。線上記帳通常在約 0.2 秒後開始同步，連續儲存會合併至下一次上傳。恢復連線時會比對 Drive 版本再補傳。版本衝突時保留本機與雲端帳目，等使用者確認。

新版使用 Google 官方授權，將帳目版本直接存進個人 Drive 的「日常留白記帳」資料夾，主網站只使用 Google Drive 同步帳目；GitHub 只放網站程式碼，不儲存任何帳目。只申請 drive.file 與基本帳號權限，Token 僅留記憶體。每次同步新增帳目版本，不覆寫舊檔；雙裝置同時更新時可選版並保留所有來源。上傳成功後會把超過 7 天、且不在最近 60 個版本內的舊快照移到 Drive 垃圾桶（每次最多 6 個），避免版本清單無限成長拖慢同步；垃圾桶仍保留 Drive 本身的還原期限。若某台裝置超過這個範圍未同步，讀取雲端時會要求先確認版本，不會自動覆蓋。

需先啟用 Drive API 並設定網頁 OAuth Client ID，並完成真人授權才能驗證。完整設定與限制：[GOOGLE_DRIVE_SETUP.md](GOOGLE_DRIVE_SETUP.md)。OAuth 用戶端 ID 由網站管理者統一填入 google-config.js；訪客只需按 Google 登入，不建立專案、不填 ID。未設定時會顯示登入尚未開放，不假裝已可使用。

## 小光 AI 點評

分析頁最上方有吉祥物「小光」的對話區。登入 Google 且本期有花費時，按「請小光點評」，小光會依收入、儲蓄、預算與花費，用 100 字內點出該省的地方、哪一天哪一類花太多，記帳狀況良好時也會稱讚。

- 提示詞（小光的個性與規則）寫在 `auth-worker/review.mjs`，只在伺服器端，前端無法改動。
- 模型為 Cloudflare Workers AI 的 Qwen3.8 27B（關閉思考模式），逾時或沒有內容時改用 Llama 3.3 70B。
- 只送出彙總：期間、收入、各類預算與實際金額、超支日、花費最高的三天、其他分類前五名。不送備註、訂閱名稱、帳號或 Email。
- 需要有效登入（Worker 的加密 Cookie）；同一位使用者 8 秒內只能請求一次，單次請求上限 6 KB。
- 點評結果只快取在這個瀏覽器，每個帳本最多保留最近 6 期；帳目改動後會標示「這是更新前的點評」。
- 這是 AI 產生的評論，僅供參考。`wrangler.toml` 需有 `[ai] binding = "AI"`。

## 備份與本機

定期匯出 JSON。未登入帳目與 Google 帳號帳目分別保存在瀏覽器，並各有前一個版本。更換裝置、網址、清除網站資料或無痕模式可能遺失本機內容。JSON 備份未加密，不要提交到公開倉庫。匯入上限 10 MB，會檢查金額、分類、日期及完成狀態。

需 Node.js 20 以上，執行網站無套件依賴：

```sh
npm start
# http://127.0.0.1:4173
npm test
```

部署前先執行 `npm run build`，由 core.js、daily.js、insights.js、ai.js、google-config.js、drive-store.js、app.js、google-sync.js 產生 app.bundle.js（網頁只載入這一支）。`npm test` 會檢查 app.bundle.js 是否為最新。

部署檔案：index.html、app.bundle.js、sw.js、style.css、paper.css、privacy.html、ledger.webmanifest、圖示。新增檔案時記得一併加入 auth-worker/index.mjs 的 publicFiles 清單，否則 spending 網域會回 404。GitHub Settings → Pages → Deploy from a branch → main / (root)。以 Pages 成功部署結果確認，勿只根據預期網址宣稱完成。

## 載入速度與離線

網頁腳本合併為單一 app.bundle.js；帶 `?v=` 的資源由 auth-worker 加上一年期 immutable 快取，index.html、sw.js 與 manifest 則維持 `no-cache` 以便改版立即生效。

sw.js 以註冊網址上的版本號命名快取：網頁本身走網路優先（離線才用快取），css／js／圖示等帶版本號的資源走快取優先。登入服務路徑 `/minimalist-ledger-auth/`、跨網域資源與 sw.js 自身一律不攔截。改版時 index.html 會註冊新版本號的 sw.js，啟用後自動刪除舊快取。manifest 維持 `display: browser`，因為 Google 登入採整頁轉址，獨立視窗模式在部分系統會跳出外部瀏覽器而拿不到登入 Cookie。

## 安全標頭與內容安全政策

auth-worker 為主站文件（index.html、privacy.html）加上 Content-Security-Policy、X-Frame-Options、Referrer-Policy 與 Permissions-Policy。腳本來源只允許自己與 Google 登入 SDK、Cloudflare 統計，因此注入的第三方腳本無法執行，也無法讀取記憶體中的 Google 或 GitHub 權杖。樣式保留 `'unsafe-inline'`，因為畫面範本以字串組出 style 屬性（金額圓點與分析長條）；這只放寬樣式，不影響腳本。

`wrangler.toml` 的 `CSP_MODE` 預設為 `report-only`：違規只記錄在瀏覽器主控台，不阻擋。確認正式網站的主控台沒有誤擋（尤其是 Google 登入與 Drive 同步）後，再改為 `enforce`。政策定義在 `auth-worker/security.mjs`，由 `tests/security.test.cjs` 檢查。

## 字體

優先使用裝置已安裝的思源宋體／Noto Serif CJK；未安裝時由 Google Fonts 載入 [Noto Serif TC](https://fonts.google.com/noto/specimen/Noto+Serif+TC)（與思源宋體同源的開源宋體），依 unicode-range 分段下載，只取實際用到的字。樣式表以 `media="print"` 載入後再切換，不阻擋首次繪製；字型未就緒前暫用系統襯線字。字體遵循 [SIL Open Font License](https://github.com/notofonts/noto-cjk/blob/main/Serif/LICENSE)。

原生日期挑選器等由作業系統繪製的視窗，外觀可能依裝置而異。v1.4 不含銀行串接、OAuth 登入或跨裝置自動合併。
